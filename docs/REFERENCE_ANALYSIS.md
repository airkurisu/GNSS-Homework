# 用精密产品离线分析 SPP 误差

本次按用户要求使用仓库同级目录中的参考文件分析误差原因。**SPP 仍只读取原来的广播导航和观测文件，未使用精密产品替换轨道、钟差、对流层或调整解算参数，也没有实现 PPP。** 三份参考原文件没有复制或上传到仓库。

## 数据与比较方法

| 参考文件 | 本次用途 |
| --- | --- |
| `WUM0MGXFIN_20241590000_01D_05M_ORB .SP3` | WHU、IGS20、GPST，300 秒间隔；在相同历元核对广播卫星位置，中心差分核对速度 |
| `WUM0MGXFIN_20241590000_01D_30S_CLK.CLK` | WHU、GPST，30 秒间隔；核对卫星钟差多项式和钟漂的量级 |
| `IGS0OPSSNX_20241590000_01D_01D_SOL.SNX` | 从 `SOLUTION/ESTIMATE` 提取 JFNG 同日坐标作为额外位置对照；不使用 `SOLUTION/APRIORI` |

日期均为 2024-06-07。文件 SHA-256、统计样本数、各项 RMS/均值/最大值及最差卫星列表保存在 [reference_summary.json](reference_summary.json)。

广播星历选择复用 SPP 的健康、时效和 Galileo 信号钟差基准规则。位置比较直接计算 SP3 的 288 个历元，不插值轨道、不作外推，不进行信号发射时刻或接收时刻间的混合比较。GPS/BDS/Galileo/GLONASS 共查询 34272 个卫星历元，其中 33680 个匹配到可用广播星历；其余明确记录为不可用。

SP3 的公里转换为米。速度使用 9 点中心差分，舍弃首尾各四个历元及缺数据窗口。径向/沿轨/法向轴由精密位置和加上地球自转项后的惯性速度构造。钟漂对照由 CLK 的相邻 ±30 秒记录求中心差分。

## 1. 参考坐标本身造成约 0.435 米偏移

SINEX 中 JFNG 的估计历元为 `24:159:43200`，ECEF 坐标（米）为：

```text
X = -2279829.23309961
Y =  5004706.43983532
Z =  3219777.34937121
```

原观测文件头概略坐标减去该坐标，在 ENU 方向约为 `(-0.41252, +0.13736, +0.00118) m`，三维差 `0.43479 m`。因此旧版仅对文件头坐标做差的东向系统偏移，部分来自参考坐标本身，不能全部归因于 SPP 算法。

最终 SPP 结果对 SINEX 坐标的全天差值如下（米）：

| 模式 | E RMS | N RMS | U RMS | 三维 RMS | 最大三维差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| GPS | 0.93480 | 0.78838 | 2.03009 | 2.36995 | 6.85815 |
| 多系统 | 0.69006 | 0.64881 | 1.71032 | 1.95508 | 11.33818 |

这是对该日 SINEX 解的差异统计，尚未统一全部测站位移和天线模型，不等同于严格独立真值精度。多系统平均表现较好，但仍存在尾部较大的误差，成功状态也不能被解释为精度保证。

## 2. 轨道计算没有出现秒级时标错位的量级

| 系统 | 轨道三维 RMS（m） | 径向 RMS（m） | 沿轨 RMS（m） | 法向 RMS（m） | 速度三维 RMS（mm/s） |
| --- | ---: | ---: | ---: | ---: | ---: |
| GPS | 1.680 | 1.367 | 0.815 | 0.525 | 0.270 |
| BDS | 4.643 | 1.413 | 4.364 | 0.752 | 0.139 |
| Galileo | 0.902 | 0.837 | 0.291 | 0.170 | 0.214 |
| GLONASS | 3.142 | 2.057 | 2.193 | 0.907 | 0.972 |

北斗总体沿轨差较大，主要异常集中于 GEO：C04、C01、C05 三维 RMS 分别约 21.25、15.10、9.34 米。该证据支持保留原有 GEO 降权；本次没有依据这些精密差值给每颗卫星另设权重。

该对照还包含广播轨道与精密轨道的参考点/模型差异。未引入 ANTEX 将卫星质心和天线相位中心完全统一，也未精细转换 GLONASS 坐标框架，因此米级差值不能全部判为传播公式错误。但对照中没有出现错误时标常见的数十公里偏差，解析速度也与精密轨道变化保持在亚毫米至约毫米每秒的量级。

## 3. 钟差不能直接混用参考基准

CLK 文件头明确说明未将时钟重新对齐到广播 GPS 时间，并记录了码偏差与天线改正处理。本次保留两种指标：

- 原始多项式钟差差值乘光速，单位米；开普勒广播钟差去掉已单独加入的周期相对论项后，与原始 CLK 比较，避免重复混入相对论项。
- 同一历元、同一系统内减去卫星间平均差值后，统计剩余差异。该处理仅用于诊断展示，不回写 SPP，也不等于完成了所有信号码偏差改正。

| 系统 | 原始钟差差 RMS（m） | 去系统公共项后 RMS（m） | 去公共项后钟漂差 RMS（mm/s） |
| --- | ---: | ---: | ---: |
| GPS | 0.422 | 0.269 | 0.405 |
| BDS | 15.102 | 12.170 | 0.116 |
| Galileo | 0.589 | 0.127 | 0.084 |
| GLONASS | 3.420 | 1.918 | 0.523 |

北斗剩余钟差差仍明显大于 GPS/Galileo，但精密产品的信号组合和卫星码偏差基准没有完全归一，不能仅凭这一项就修改 TGD 符号或把精密钟差代入 SPP。GLONASS 的时钟约定同样需要单独注意。这里仅把结果作为误差来源线索。

## 4. 定位跳点能从 SPP 自身残差中直接发现

第一轮正确性修复后、加入粗差筛查前，GPST 周内秒 `463380`（08:43:00）的多系统解中，E09、E11 的伪距后验残差分别约 `+50.98 / -33.57 m`，C59 约 `-87.76 m`。这些异常已经在广播星历 SPP 内部可见，无需精密产品提供判据。残差同时受当前受污染位置和系统钟差影响，因此单个大残差不能单独证明该卫星本身有故障。

为此增加了保守的伪距粗差检查：用 1 米单频码噪声及 IF 系数估算噪声尺度，结合当前加权几何的残差投影方差；至少两个冗余观测时以 6σ 筛查，一次剔除一颗并重新定位，最多五颗。阈值没有通过 SINEX/PPP 坐标调参。

全天多系统有 51 个历元各剔除一颗观测，GPS 模式没有触发剔除；全部 2880 个历元依然成功定位和测速。多系统相对 SINEX 的三维 RMS 从这一轮未筛查版本的约 `2.22973 m` 降至 `1.95508 m`，最大差从 `20.77254 m` 降至 `11.33818 m`。这说明基本观测质量控制比强行贴合精密轨道更直接地解决了部分跳点，但剩余尾部误差仍需改进。

## 5. 剩余测速波动更应检查观测与几何

最终多系统静态速度 E/N/U RMS 约 `0.01120 / 0.01183 / 0.02789 m/s`。卫星速度对 SP3 的差仅约 `0.00014–0.00097 m/s`，去公共项后的卫星钟漂差也低于约 `0.00053 m/s`。

据此推断，剩余测速波动不太可能主要由卫星解析速度公式的大量级错误造成，更值得检查多普勒观测噪声、双频组合的噪声放大、几何条件和未建模偏差。这个比较不是完整误差预算，也不能代替带真值动态轨迹的验证。垂直方向较弱的几何与标准对流层模型，仍是位置和速度垂直分量表现较差的合理分析方向。

## 复现（可选）

下面按 Windows Ninja 构建目录示例运行，文件名中的空格需要保留。没有这些文件也能正常构建、测试和运行 SPP。

```powershell
python tools/compare_precise.py --sp3 '../WUM0MGXFIN_20241590000_01D_05M_ORB .SP3' --clk '../WUM0MGXFIN_20241590000_01D_30S_CLK.CLK' --sinex '../IGS0OPSSNX_20241590000_01D_01D_SOL.SNX' --nav data/brdc1590.24p --state-dump build/gnss_state_dump.exe --output build/precise-comparison --positions build/gps.csv build/multi.csv
```

输出 `broadcast_states.csv` 保留广播卫星 XYZ、速度、含相对论钟差/钟漂、纯多项式钟差/钟漂、TOE/TOC/TGD/数据源；`differences.csv` 保存逐星逐历元差值；`summary.json` 保存完整统计。数据量较大的 CSV 均留在忽略的构建目录。

格式依据：[IGS SP3-d](https://files.igs.org/pub/data/format/sp3d.pdf)、[IGS 精密产品说明](https://igs.org/products/)。相对论钟差约定另核对 [RTKLIB preceph.c](https://github.com/tomojitakasu/RTKLIB/blob/master/src/preceph.c)。
