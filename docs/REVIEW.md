# 项目审查与修复记录

审查基线：`37bd075`。覆盖入口、全部头文件和实现文件、CMake、README，以及随仓库提供的导航和观测数据。验证数据为 JFNG 测站 2024-06-07 全天 2880 个历元。此次保留 C++14 和课程设计的广播星历双频伪距 / 多普勒解算方法。

## 已修复的问题

| 模块 | 原问题及影响 | 修复 |
| --- | --- | --- |
| 多系统多普勒 | 卫星钟漂使用正号，接收机钟漂在预测值中使用负号，但设计矩阵使用正号；非零接收机钟漂会被反复错误累加 | 统一为 `Pdot = geometric_rate + receiver_drift - c * satellite_drift`；线性速度方程直接解算一次，结果结构提供各系统钟漂 |
| 坐标转换 | ECEF→大地坐标迭代没有更新用于计算的 `z`，高程也使用旧值；ENU 使用地心纬度 | 正确迭代椭球纬度和高程，统一使用大地纬度旋转，处理极点和零坐标 |
| 卫星钟差 | 钟差多项式使用 TOE 而不是 TOC；钟漂缺少相对论改正导数 | 轨道与钟差分别使用自己的参考时刻，补齐解析钟漂 |
| 北斗时间 | BDT 修正散落在轨道计算中，导航时刻仍混用原始 BDT 与 GPST，周界容易错配 | 读取时统一转成 GPST；额外保存原始 `toeSow`，升交点公式仍使用广播系统周内秒 |
| 信号与频率 | 文件头选定一次观测码后，该卫星对应字段缺失也不再回退；E5b、B2、B1C 等回退后仍套原来的固定频率 | 每颗卫星、每个历元选择可用信号；按实际频段计算频率；不支持的 B1C 组合明确排除 |
| 群延迟和 Galileo 钟差基准 | 北斗只读取 TGD1；Galileo 不区分 F/NAV 与 I/NAV 钟差所对应的频率组合 | 读取两项 TGD，B1I/B2I 使用两项改正；Galileo 按 RINEX 数据源位选择匹配的 E1/E5a 或 E1/E5b 星历 |
| 星历选择 | 速度解算没有有效期限制，健康标志未读取；定位和测速规则不一致 | 共用每颗卫星的导航索引，筛选健康星历，统一限制 GPS 7200 秒、BDS 14400 秒、Galileo 10800 秒、GLONASS 1800 秒 |
| 多系统矩阵 | 用原始观测预先创建钟差列，某系统的卫星经过高度角/星历筛选全被剔除后，仍保留全零列 | 每次根据实际参与方程的观测创建系统参数 |
| 数值计算 | 正规方程显式求逆放大条件数；仅判定主元严格等于零；耗尽迭代仍可能返回成功 | 解算改用 Householder QR 和秩检查；PDOP 保留无权几何矩阵求逆；位置和全部钟差改正同时收敛才成功 |
| 定位 / 测速一致性 | GPS 测速固定减 0.075 秒、缺少地球自转项；发送时刻没有扣除卫星钟差 | 共用基于观测伪距和卫星钟差的发送时刻；统一加入地球自转影响 |
| 伪距粗差 | 实测全天存在几十米残差的观测仍进入成功解，产生明显定位跳点 | 增加基于 IF 噪声与残差投影方差的保守 6σ 检查；有足够冗余时逐颗剔除，最多五颗，完全不使用精密产品判据 |
| 缺测和失败状态 | 零多普勒当作缺测；GPS 测速失败仍显示零速度；多系统测速失败连位置也不输出；无参考坐标时输出零位置误差 | 用 NaN 区分缺测；位置与速度分别标记有效性，CSV 提供状态，无效结果显示 `nan` |
| RINEX 读取 | 短行 `substr` 可能抛异常或读入不完整导航记录；事件记录被误当作观测；无格式校验；异常被大量吞掉 | 完整记录读取，版本/类型/字段/历元计数/重复卫星检查；跳过适用事件；不支持的头更新和非单位缩放明确报错 |

| 可维护性和入口 | GPS 与多系统重复两套算法；伪交互菜单；写死 02–06 时段、相对文件路径、全局静态链接选项；无测试/使用说明 | 共用 `SPPSolver`；保留旧流程包装接口；命令行选择模式/系统/文件/时段；默认全天；CMake 库与测试目标，移除强制静态链接 |

## 验证方法

1. Windows、MinGW GCC 15.2、Release 构建，通过 `-Wall -Wextra -Wpedantic` 编译；没有本次构建警告。
2. C++ 回归通过 214 个检查，另有 Python 离线分析工具测试。CTest 回归覆盖日期/历史跳秒/跨周、坐标转换、数值秩检查、星历速度与钟漂的中心差分、TOC/TOE 不同的钟差、短文件和事件、按卫星信号回退、缺失与零多普勒、北斗跨周和 TGD2。
3. 合成数据设置已知接收机速度 `(12, -3, 1.5) m/s`，GPS/BDS 接收机钟漂分别为 `20 / -30 m/s`；同时验证零初值定位、缺星历系统、缺多普勒、过期/不健康星历。合成位置采用精确地球自转矩阵生成距离，与解算器的一阶距离改正不同；轨道状态和对流层仍复用本项目模块，因此不是完整独立外部软件验证。
4. 实测数据按全天运行 GPS 和多系统模式，均为定位 `2880/2880`、测速 `2880/2880`；另外从零坐标运行 02:00–02:06 的 13 个历元，均成功。自动回归另抽查每两小时的实测解算。
5. 已添加 Linux / Windows GitHub Actions 工作流。远程执行情况以 GitHub 实际检查为准，本地验证不代表远程 CI 已通过。

## 仍然欠缺的部分

- **观测质量控制**：没有按 C/N0、接收机噪声、IF 组合放大系数建立完整方差模型，已加入基本伪距粗差筛查，但没有独立多普勒粗差检查、RAIM 或完整性检验。成功状态表示数值求解成功，不代表排除了粗差。
- **码偏差与测站模型**：GPS C1C/P1 等 DCB、GLONASS 接收机频间偏差、北斗码偏差、天线相位中心和测站位移模型尚未完整处理。对流层使用标准气象参数和椭球高，不能替代实测气象与正高改正。
- **精度独立验证**：已用用户提供的同日 SINEX、SP3 和 CLK 进行离线误差分析（见 [参考分析](REFERENCE_ANALYSIS.md)）；仍需独立成熟软件及有真值的动态数据评估测速。当前静态一天的数据不能证明动态场景精度。
- **格式与系统范围**：支持 RINEX 3.00–3.04 的明确子集，不支持 RINEX 2/4、压缩文件、BDS B1C 等新信号完整偏差模型、QZSS/SBAS/NavIC 定位。RINEX 3 每颗卫星使用一条可变长数据行，不支持私自按 80 列折行的非标准观测记录。读取时完整消费不支持系统的导航记录，再跳过。
- **特殊 RINEX 语义**：中途头更新、非单位观测缩放、非零历元接收机钟差偏移明确拒绝；不同信号的 Galileo 健康位采用保守的整字段零健康筛选。未宣称实现 RINEX 所有可选头记录。
- **时间和坐标框架**：跳秒表截至 2017-01-01 生效项；未来若新增跳秒需要维护。不能精确表示 UTC `23:59:60` 标签。GST/GPST 小偏差由系统钟差近似吸收，PZ-90/WGS84 框架差未精细改正。
- **工程扩展**：目前将整个观测文件读入内存；多日、大规模处理可改成流式历元读取。广播星历有效期采用固定保守阈值，没有逐条使用 fit interval 扩展覆盖。迭代定位只适用于常规近地接收机场景。
